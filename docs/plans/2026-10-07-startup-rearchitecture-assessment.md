# 启动架构重构评估：常态与偶发慢启动

日期：2026-10-07。状态：启动重构仍为候选设计，尚未授权实施；用户已确认将图片文件持久缓存纳入 A，并要求兼容 B。本次仅维护计划文档，未修改代码、操作设备或部署。

## 决策摘要

有理由评估重建启动路径，但不建议重写整个产品。推荐候选 A：保留通用 WebView、hanaccount、hanui 的产品分工，重建首阶段依赖调度与静态资源任务生命周期。目标同时包括缓存命中启动和偶发重传慢启动，不能只改善后者就宣称完成。

A 另包含历史图片的本地文件持久缓存：首次获取成功后保存原始二进制，下次 App 冷启动在权限与附件引用确认有效后复用文件。它独立改善对话阶段的图片显示，不计入第一阶段弹窗的启动收益。完整会话历史持久缓存暂未纳入本次实施范围，仍需另行评估官方恢复与同步接口。

在下述阶段预算成立时，A 的中性工程估算约为 **4.9–6.1 秒**，可概括为约 5–6 秒；理想条件约 3.7–4.6 秒，不能作为承诺。若现有时间主要属于必要 CPU、必要服务器响应，或官方没有可用的分段加载接口，结果可能仍在 **7.1–7.5 秒附近**，届时不值得扩大重构。

候选 B 在 A 上增加版本化资源分发和轻量动态引导，条件化预算约 **3.9–5.0 秒**，但维护代价明显更大。它不是把当前 11 MB 文件复制进 APK；后者已经被本地缓存覆盖，不能消除解析和初始化成本。

“减半”约需达到 3.5–3.7 秒。现有证据不足以支持将其作为可靠预期。下列数值是供决策的预算模型，不是统计结果、性能承诺或用户已确认的验收线。

## 目标与测量口径

第一阶段终点保持为：打开 App 后，**同一真实官方预览说明弹窗可见且具备原有交互功能**。弹窗是否出现、确认行为与持久化语义保持一致。不能提前显示仿制静态弹窗、主页、加载占位，或只提前发 pageReady 来冒充提速。

第二阶段“最近非空对话就绪”独立计时，本轮架构判断不以它替换第一阶段。但第一阶段收益也不能靠把所有工作挪到第二阶段获得：实验必须附带记录最近对话历史与输入就绪时间，披露任何回退。

## A：保留产品分工，重建启动关键路径（推荐）

### 三层职责

- 整体：形成明确的启动依赖表，区分必须参与第一阶段的引导、认证、配置和弹窗，与可后置的设置、次要交互、观察器。使用官方支持的加载接缝安排依赖，不修改官方业务核心。
- 插件：hanaccount 的轻认证引导尽早启动同源认证查询，AuthSession 仍唯一持有状态、请求合并、失效和 dispose；hanui 的首阶段装配只消费必要能力，非必要副作用按实际功能激活。任务拥有 ready/failure/dispose，不增加全局状态总线。
- App：BrowserRuntime 继续只拥有浏览器和文档；资源模块拥有资格校验、按安全代际合并任务、下载、原子发布和清理。文档只是消费者。既有预热保留，不新增 DSH 原生业务连接。

### 关键路径的变化

目标形态为：WebView/文档 → 轻量引导 → **必要脚本激活与有效认证/动态配置并行** → 官方弹窗实际绘制。下一阶段按原有业务契约进入最近对话。

可能消除的是非首屏插件对首阶段的阻塞、重复资源生产、可并行却晚发起的认证等待。仍须支付 WebView 冷启动、必要 JS 处理、真实授权/配置响应和绘制成本。脚本分文件本身不减少工作量；只有不再阻塞该终点才计收益。

认证前移有两个不同层次：

1. 优先评估在受保护文档加入不含身份数据的轻量引导，提前同源请求，并由唯一 AuthSession 接管同一请求/结果。必须遵守 CSP、文档寿命、失效规则，不能用旧 scope 作为授权。
2. 将认证快照放进动态 bootstrap 只有在请求级处理且双身份已校验时才可行。线上 alpha1 的 `WebServer.collectIndexInjections()` 只发 table，没有 request 参数，**不能把某用户认证快照放进全局 injection table**。[alpha1 webserver:345](../../artifacts/deploy-20261007/alpha1-contract/dsh-host-webserver/lib/index.js#L345)。因此不能把请求级快照作为现成可用能力计入可靠收益。

### 资源模块的小接口

候选接口只需要 acquire(assetDescriptor, consumerLease)、release(consumer)、invalidate(securityEpoch)。内部区分资源生产任务与文档消费资格：文档退出可以取消消费，但不必自动取消仍被合法消费者使用的相同不可变资源生产。

描述符包含来源、版本身份和安全代际；来源/权限改变、换站、退出与清理必须使旧生产任务失效，禁止晚完成重新写回已清理缓存。现有静态资源模块只接纳严格校验的静态资源，保留 MIME、重定向、no-store/private、Vary、Set-Cookie 限制，不扩展到 HTML、认证响应、历史消息和图片。图片使用下节独立的私有文件缓存与授权规则。[StaticAssetCache.kt:219](../../app/src/shell/java/com/labteto/dshmobile/browser/StaticAssetCache.kt#L219)。

该接口隐藏任务合并、取消、发布和失败兜底，具有实质职责；无需新通用下载框架或进程级任务平台。是否改变首次完整缓冲/落盘顺序另由测量决定，不能同时引入复杂流式发布。

### A 新增：历史图片文件持久缓存（兼容 B）

**决定与目标。** 用户已选择直接保存图片文件，而非只保留内存 Blob URL。首次成功获取的原始图片字节写入 App 私有缓存目录；进程退出后文件仍可复用，在容量淘汰、清理或失效时删除。命中应省掉重复附件传输，仍需本地读取、解码与绘制。缓存是可丢弃的副本，不是永久备份，也不承诺未经授权的离线访问。

**现状与接缝。** 已核线上 alpha1 的 HistoricalImageCache 主要保存按会话共享的 pending/Blob URL，不能作为跨 App 重启的图片文件缓存。[实际图片实现](../../artifacts/deploy-20261007/alpha1-contract/dsh-client-ui-conversation/lib/client.js#L3453)。实施前确认对应版本能在官方附件读取/图片解析入口接入 Adapter；当前未确认存在公开持久缓存扩展接口。若缺少受支持接缝，先明确适配方案与升级成本，不以扫描 DOM、替换显示 URL 或全局拦截 RPC 代替数据层接入。

| 层级 | 责任 |
|---|---|
| 官方数据模块 / 网页插件 | 拥有附件身份、引用、版本及有效授权，决定读取本地或获取服务器附件；合并同附件请求、安排可见图片优先级；不复制官方当前会话状态 |
| App | 提供通用私有文件存储与受控读取能力，负责临时写入、完整发布、容量淘汰和清理；不解析消息、不保存认证凭据、不决定用户是否能访问某个会话 |
| 缓存 Adapter | 将网页授权的附件描述映射成不透明文件键与句柄，协调消费取消、写入失效和错误回退；集中隔离官方版本差异 |

**文件与身份。** 文件键至少隔离站点、认证作用域、会话及附件身份，并带缓存 schema 和已确认的附件版本。只有核实附件 ID 不可变时才能直接作为版本身份；不可假定它等于内容哈希。若提供内容哈希则校验，若允许同 ID 更新则必须包含修订号或重新验证。元数据保存 MIME、实际长度、完整状态与访问时间；保留原始二进制，不持久化 Blob URL，不把 Base64/JSON 大字符串当文件传输格式。桥只传小型描述符与不透明句柄，二进制采用受控传输路径；具体入口在实现设计时根据 WebView/CSP 和官方读取契约选择，不开放任意文件路径或全局 file:// 访问。

**读取与写入流程。**

1. AuthSession 确认当前认证作用域，官方会话确认可访问且历史中存在该附件引用，才查询对应本地文件；文件存在、完整且版本有效时直接本地读取，重新创建该文档使用的显示 URL。
2. 缺失、损坏或版本变化时沿用已授权的附件获取路径。同键任务合并，使用有界并发，优先首屏可见图片；后台预取不能阻塞第一阶段启动。
3. 获取成功后写临时文件、验证长度/可用的完整性信息，再原子发布文件与有效索引；半文件不可被当作命中。写入或配额失败仍允许显示本次已获取图片，不把持久缓存失败变成会话加载失败。
4. 文档退出释放显示 URL 和消费者；文件保留供同一有效作用域的下次打开复用。退出登录、权限撤销、删除会话/附件、换站或显式清理使对应条目失效，旧异步任务不能在清理后重新发布。未知权限或网络错误不自动当作退出，也不授予缓存访问权。

当前 resumeScope 是每次登录的作用域，同一次有效登录可跨进程重启复用；重新登录后不能自动复用旧分区，不将其冒充稳定账号 ID。服务器删除或撤权尚未同步时，必须遵守官方授权/引用校验契约，不把本地存在当作仍有效的证明。

**容量与运行预算。** 定义总容量、单文件上限、并发上限与按最近访问淘汰规则，实施时依据真实图片大小和设备测量确定默认值。限额与文件 I/O 在 App 内管理；访问错误和淘汰表现为可回退的 miss。初始化、扫描与淘汰按需在后台进行，不给第一阶段新增全目录扫描或等待。大图片解码也需有界，避免缓存命中后仍因并发解码阻塞界面。

**A 到 B 的复用。** 图片缓存身份与 schema 不绑定 JS/application batch 的 rev；B 的程序资源更新或回退不应无条件清空有效图片。程序静态资源集与私有附件文件保留独立命名空间、版本规则、容量和失效策略。B 继续复用同一图片缓存 Adapter、文件存储和授权所有者，只在受控读取入口或 schema 确有变化时做显式迁移；共享清理机制的安全代际，不把图片打包进程序 manifest，也不另建第二套图片缓存。

**交付顺序。** A 先固定身份/失效契约和官方接缝，再增加文件存储与 Adapter，然后接入图片获取、优先级与容量淘汰，最后验证真实冷启复用。B 在此基础上扩展程序资源分发，不推倒图片缓存。最近对话路由问题与完整历史持久缓存分别验收，不由本节替代。

## 数值模型：明确是假设预算

现有记录可按边界近似拆成：2.13 + 1.50 + 0.80 + 1.26 + (1.39–1.75) = 7.08–7.44 秒。后两项只是资源结束→visual、visual→弹窗的区间，**不是已经归因的 CPU 或认证成本**。

对 A 使用目标模型：

`T_A = L + H + max(C, A) + P`

- L：open→loadUrl，先固定为当前近似 2.13 秒，不假设已有预热还能节省它。
- H：文档/引导到可发起必要并行工作的时间。
- C：必要脚本交付、解析与激活路径。
- A：同阶段开始的有效认证和必需动态配置路径；CPU 争用、依赖或服务响应若阻止并行，不能使用 max 模型。
- P：两条必要路径完成后，到真实弹窗可用的剩余渲染/调度时间。

| 情景 | H | C | A | P | 算式结果 |
|---|---:|---:|---:|---:|---:|
| 中性工程预算 | 1.2–1.5 | 1.2–1.7 | 0.8–1.6 | 0.4–0.8 | 4.93–6.13 秒 |
| 理想预算 | 0.7–1.0 | 0.7–1.1 | 0.5–1.0 | 0.2–0.4 | 3.73–4.63 秒 |
| 保守反例 | 保留原有依赖与成本 | 无有效减量 | 已并行或必须后置 | 现有尾段不可移除 | 约 7.1–7.5 秒，可能无净收益 |

预算依据与可推翻条件：当前脚本资源结束到 visual 为约 1.26 秒，资源交付约 0.80 秒，两者共约 2.06 秒；中性 C 要求减少或移出约 0.36–0.86 秒，而不是假设消除全部大包。H 相对当前约 1.50 秒只预留 0–0.30 秒改善。P=0.4–0.8 秒要求当前弹窗尾段的其余等待能被前移/重叠；**此项尚未证明，是估算最敏感的假设之一**。A 的数值也是实验预算，当前没有相应请求级数据支撑为实测耗时。如果这两个前提失败，应立即按保守情景重算。

所以可向决策者表达“中性期待约 5–6 秒、约两至三成改善”，但不能把这一表达变成已证实收益。区间按预算上下界相加，不是置信区间。

## B：在 A 上增加版本资源分发与轻量动态引导

App 持有按站点/安全代际隔离、原子安装的版本静态资源集；服务器提供小型动态引导及版本选择，插件按所选版本装配。必要静态资源可预先安装，更新失败回退已验证完整版本，不能混用半新半旧资源。

文档认证、配置和版本有效性仍由服务器确认；不离线复用用户 HTML、认证快照或 scope。资源继续保持合法同源与 CSP/完整性语义。APK 内置一个固定 DSH 页面、双 WebView 接力或先显示本地假弹窗均不作为该方案。

B 直接沿用 A 的历史图片文件缓存，按前述独立命名空间与 schema 兼容规则管理。B 的程序资源版本变化不会自动改变附件身份或授权语义；升级/回退需要回归已缓存图片的命中、读取、清理与失效行为。

需要确认官方可让轻引导与完整应用在**同一文档**内接续，并保留真实弹窗交互；如果只能第二次整页导航，收益模型失效，不建议实施。此项尚未由线上 loader 契约证明。

目标模型为 `T_B = 2.13 + M + max(C, N) + P`，M 为小引导/版本选择，N 为仍必需的远程认证与配置。若 M=0.15–0.40、C=1.2–1.7、N=0.8–1.6、P=0.4–0.8 秒，则为 **3.88–5.03 秒**。这里沿用 A 的脚本减量，B 的额外收益主要来自不再让完整动态文档/插件发现延迟挡住本地静态处理。

如果必要远程响应 N 实为 1.5–3.0 秒，结果变为约 **4.18–6.33 秒**；若还需原样加载原文档，就应回到 A 预算。单纯把已缓存大包放 APK，仍保留原有引导、CPU 和弹窗等待，不能使用 B 的较好区间。

## 路径取舍与工作量

| 路径 | 改造范围 | 相对工作量 | 维护代价 | 判断 |
|---|---|---|---|---|
| A | 启动依赖表、轻认证引导、必要插件激活、资源生产/消费解耦、历史图片文件持久缓存、真实兼容测试 | 中；新增文件缓存、读取 Adapter 与清理验证，须重新估量总范围 | 需匹配官方 loader 和附件读取接缝；现有业务所有权保留 | 推荐先做最小实验，满足门槛后实施 |

## 最小可证伪实验（仅方案，尚未执行）

实验一验证常态收益：锁定线上对应 loader、APK、插件版本和弹窗状态，在隔离环境比较基线与一次性的 A 关键路径原型。将同源认证提前、只按真实依赖延后已确认非首阶段工作；全程使用真实 Cordis 与生成 bundle。以设备单调时间关联打开、文档、请求、任务执行与实际绘制，分别记录 C/A/P。不得仅禁用插件或提前发 ready。

预先安排多轮交替运行，例如各 10 次冷进程缓存命中、另列冷缓存与热进程；报告每次结果和范围，样本不足不作稳定分位数宣称。检查同一真实弹窗的可见/交互、双身份验证、配置正确性，以及第二阶段是否回退。若 A 已并行、剩余关键工作不能减量，或保留完整行为就回到约 7 秒，推翻中性估算，不扩大实现。

实验二验证偶发慢尾：用脱敏任务 ID 关联 native cache、文档 lease、请求落地和 WebView 默认兜底；对照相同 URL/版本在导航切换、认证变化、资源失败和进程退出时的行为。只有复现了重复生产或丢失后重发，才把对应异常归因于生命周期。修复后需证明单资源不会无意重复传输、正常失败可重试、旧任务不能越过清理安全代际发布。若异常其实来自源站/网络，保留该事实并单独处理，不能靠缓存架构承诺消除所有 20 秒事件。

实验三仅在 B 值得考虑时进行：证明官方允许同文档轻引导接续；保留真实动态校验和弹窗，用版本完整性失败/升级/回滚对照。若出现双重初始化、整页重载或把认证结果持久化当权限，则直接否决该实现。

图片缓存独立验收：同一有效登录、同一会话及同一附件版本，先获取并完整入库，随后实际关闭并重开 App。分别记录历史可用、首屏图片开始/完成、附件网络请求与字节、本地读文件、解码和绘制；确认再次打开不重复下载已命中的图片字节，允许必要的认证/引用/版本校验请求。对照缓存为空、缺失/损坏、容量淘汰、并发取消、删除、退出/重新登录、换站、清理期间晚完成以及 B 程序资源升级/回退。不得仅凭显示 URL 或 native 文件存在认定缓存命中。图片收益不加入第一阶段 4.9–6.1 秒估算，暂无图片显示时间的数值承诺。

## 建议实施门槛

建议在用户认可后，先批准最小实验，暂不批准整套重建。候选 A 的继续门槛可定为：完整语义下缓存命中首阶段有一致、至少约 1 秒的净改善，且异常重复传输问题有独立闭环，第二阶段无实质回退。约 5–6 秒是候选工程目标；约 1 秒是建议的投入价值门槛，均待用户决定，不是已设定的验收要求。

若只有慢尾改善而常态不改善，不能视作本轮双目标完成；应向用户报告 A 不足以兑现常态目标，并依据实测决定 B 或停止。若必要冷启动 CPU/响应占比很高，停止重构也是正确结论，避免为了数字引入一套长期负担更大的产品架构。

用户确认的图片文件持久缓存另列交付条件：跨 App 重启命中、相同有效附件不重复传输、正确授权与失效、容量有界、与 B 升级/回退兼容。启动目标达成不代表图片目标已完成；计划纳入不代表已授权代码实现或部署。
