# 会话优先启动与历史持久缓存需求

2026-10-07。用户补充的明确需求与本地代码核对结果；不是实现或部署完成记录。

- 常态启动直接恢复上次访问的非空会话，不把官方欢迎弹窗作为每次启动必经入口。定位更新后恢复失效的回归；欢迎状态与会话选择分别检查，不通过伪造确认或直接移除 DOM 解决。
- 本地历史会话要求持久缓存，不能仅保存 sessionId 或图片。至少覆盖最近会话的首屏消息、显示所需结构及历史分页进度；普通进程关闭后保留，随后通过官方同步校验。存储格式、历史范围和官方 renderer 接入仍需核对，不承诺已具备接口。
- 启动验收终点调整为真实最近会话首屏可读、输入可操作；本地缓存首屏与服务器同步完成另记时间，无目标时主页另记。此前 7.75 秒官方弹窗口径仅保留作历史基线，不与新终点直接比较。
- 评估版本化本地 HTML 引导，保持原 HTTPS origin、Cookie、CSP、资源版本与认证语义；当前仅 JS/CSS 被 App 缓存，尚无本地 HTML 首屏。
- 评估缩减首屏脚本依赖与分批调度。独立资源可并行传输；依赖初始化与主线程执行不可简单同时运行。线上 alpha1 loader/build 能力必须单独验证，不能以本地新源码代替部署证据。

核对：hanui `startup.js` 仍装配 createStartupCoordinator 与 localStorage TargetStore；旧无 scope key 被删除，新 key 仅接受匹配 scope 的目标。因此恢复逻辑未在当前本地源码中删除，但旧偏好迁移、scope、官方能力与导航竞态均需设备证据确定，尚未定位回归原因。

## 2026-10-08 优先级与验收补充

用户明确优先解决历史反复加载：打开过的每个会话都要将已取得的历史数据持久保存，而非仅缓存最近会话或 sessionId。切到其他会话再返回、页面重建、关闭进程再启动均复用本地记录。初次打开拉取未缓存数据；后续仅拉取服务器变化部分，包含新增、修改、删除，不能把全量拉取后本地 diff 称为增量传输。已经加载的历史页保留；未加载部分按需取得。

验收必须同时检查真实可读页面、网络历史传输范围以及杀进程后的磁盘恢复：A→B→A、force-stop 后重开 A、无变化时零全量历史传输、有新增/修改/删除时正确合并、落盘事务完成后重启数据仍可读。认证/同步与本地缓存独立计时，不把必要的版本查询或连接建立误称为历史重载。

目前是需求确认与接口研究，尚未实现。优先核验部署 alpha1 的历史游标、版本及差量协议和官方渲染接入；本地官方新源码不能证明部署版本支持。若只提供全量接口，必须明确协议缺口，不能声称已满足“只拉变化部分”。
